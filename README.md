# Mini-projet jeu vidéo avec Pygame

## Présentation

Votre objectif est de réaliser un jeu vidéo en python et avec l'aide de la bibliothèque [pygame](https://www.pygame.org/docs/).

Pygame est une bibliothèque largement utilisé pour s'initier au développement de jeu vidéo.

## Déroulement du projet

### 1. Les groupes

Votre groupe peut aller de 1 à 3 personnes.
> Seul on va plus vite, à plusieurs on va plus loin.

### 2. Cahier des charges (ou *Game Design Document*)

Vous devrez rédiger un cahier des charges qui listera les fonctionnalités, l'équipe ainsi que les logiciels/applications/bibliothèques utilisés (tous).

Il faudra faire attention à bien s'y tenir et donc de ne pas vouloir  faire trop de fonctionnalités. Il vaut mieux ne pas faire toutes les fonctionnalités du cahier des charges plutôt qu'en faire qui n'y sont pas listées.

Vous trouverez un [bon exemple ici](https://hermita-game.github.io/docs/Cahier%20des%20charges.pdf) du cahier des charges que vous devrez réaliser.

> [!NOTE]
> Vous n'êtes pas obligé d'expliquer l'ambiance ou l'histoire du jeu. Vous serez limités dans le temps ! Alors, ne vous perdez pas trop en chemin.

### 3. Organisation du travail

Afin de mieux vous organiser dans votre projet, il est possible d'utiliser des méthodes de gestion de projet telles que Kanban, Scrum ou Agile. Nous allons partir sur Kanban, qui est plus facile à prendre en main. Il existe différents sites comme Trello, GitHub Projects, etc. Mais un fichier Excel fait aussi très bien l'affaire. Le tout est de faire trois colonnes principales :

| A faire | En cours de réalisation | Fait |
| --- | --- | --- |
|  |  |  |

Après cela, vous écrivez l'ensemble des tâches et des fonctionnalités dans la colonne "À faire ". Dès que quelqu'un s'occupe d'une fonctionnalité, il déplace la case dans la colonne "En cours de réalisation" et ainsi de suite.

> [!TIP]
> Utilisez un code couleur pour mieux vous organiser.

### 4. Où mettre votre code ?

Pour pouvoir travailler sur votre code, il vaudra mieux utiliser Git et, comme vous venez de créer un compte GitHub, autant l'utiliser, non ? Faites en sorte qu'une personne crée un répertoire (ou repository) et vous ajoute comme collaborateur dessus.

Je vous recommande de ne pas travailler sur le même fichier en parallèle ; autrement, lorsque vous ferez un commit, il risque d'y avoir des conflits et cela risque d'écraser le code de l'autre.

## C'est partie !

Amusez-vous bien.
